# Easy triage

Read every open `needs-triage` issue and sort it into one of two lists: **moving** to `ready-for-agent`, or **staying** in `needs-triage`. An issue moves when it has a clear winner: one fix that the issue or its comments already point to, or one that a short investigation in the code settles. Everything else stays.

Moving an issue hands it to an agent that works alone, so nothing changes on the tracker until the person says yes.

## 1. Collect

Issues live in `pkhex-web/issue-tracker`; code lives here. Run `git fetch origin`. Read code on `origin/main` (`git grep -n <term> origin/main`, `git show origin/main:<path>`), since local `main` falls behind.

List the issues, oldest first, and drop any labelled `epic`: they are not part of this run and appear in neither list.

```bash
gh issue list -R pkhex-web/issue-tracker --label needs-triage --state open --limit 200 \
  --json number,title,body,labels,comments,createdAt
```

Done when you hold the body and every comment of each issue.

## 2. Judge each issue

Work through them one at a time, yourself. For each:

- **Check it still holds.** Find the code the issue is about. If `origin/main` already does what it asks, or another open issue covers it, it stays, with that evidence.
- **Look for the winner.** Is there one fix the issue or a comment argues for, with no open question left? If there are several options, can the code, the tests, `CONTEXT.md` or `docs/adr/` pick one? That is the short investigation: reading, grepping, running one test. Do it now and note what you found.
- **Decide.** It moves if you can name the change and the tests that prove it (in `PKHeX.Facade.Tests`; E2E only where ADR 0001 allows). It stays if it needs a product choice, a design the person has not made, a change to a fork under `external/` (that is `ready-for-human`), access only a human has (a save file, a third-party dashboard), or a real investigation such as reproducing a bug.

Done when every issue sits in one list with a reason you can back with a file, a test or a comment.

## 3. Show both lists

In the terminal, short:

**Moving**: for each, the number and title, the winning fix in one line, where it came from (the issue, comment X, or what you found in the code), and what the brief will add.

**Staying**: for each, the number and title, why it stays, and what would settle it (a decision to make, a question to answer, or "close it, already on main").

Ask whether to go ahead. The person may move items between lists or change a fix. Write nothing to the tracker without a yes.

## 4. Push to the tracker

Load `/unslop` and read `docs/agents/issue-tracker.md`. For each moving issue:

1. If the body and comments do not already carry everything an agent needs, post an agent brief as a comment, following [AGENT-BRIEF.md](AGENT-BRIEF.md). Start it with `> *This was generated by AI during triage.*`. Put what you found in step 2 into it, since the agent will not see this conversation. Leave out emails, save file contents and anything personal.
2. If it depends on another open issue, add the blocked-by edge (see `docs/agents/issue-tracker.md`).
3. `gh issue edit <n> -R pkhex-web/issue-tracker --add-label ready-for-agent --remove-label needs-triage`.

Leave the staying issues untouched, unless the person asked for something on one of them in step 3.

Done when every moving issue carries `ready-for-agent` and not `needs-triage`. Report each link, and say which ones got a brief.
